## 1. 实验室定位

AUTOVERSE TECH LAB 是 AUTOVERSE 产品的**技术研究中心、架构验证平台、设计规范库与 AI 开发知识库**。

它不是 AUTOVERSE 产品本身，也不是产品代码仓库。它的职责是：

| 职责 | 说明 |
| --- | --- |
| 产品规划与世界观研究 | 沉淀产品方向、展品体系、知识结构的研究成果 |
| 前端框架与 3D 引擎选型 | 以官方资料 + 可运行原型为依据做技术决策 |
| 3D 渲染与视觉技术实验 | PBR、后期处理、Shader、粒子、WebGPU 等 |
| UI/UX 设计体系建设 | 自主 Design System，不依附任何现成组件库 |
| AI Skills 与开发工具链研究 | 让 AI 工具在规范内高效、安全地产出 |
| 汽车模型与数据资源研究 | 资源来源、许可合规、处理流水线 |
| 性能/兼容性/工程架构验证 | FPS、内存、加载、浏览器兼容、测试策略 |
| 输出经过验证的技术方案 | 向未来正式的 AUTOVERSE 产品仓库交付结论 |

**核心价值主张：每一项进入正式产品的技术决策，都必须有研究记录 + 可复现验证，而不是凭文章、宣传或直觉。**

## 2. 与 GEWU（格物）的关系边界

AUTOVERSE TECH LAB 与 GEWU（格物）是**两个完全独立的产品**。

允许的行为：

- 借鉴 GEWU 中与 3D 渲染、工程架构、AI 工作流相关的**通用技术经验**；
- 引用 GEWU 中已被验证的通用结论（需标注来源为经验借鉴）。

禁止的行为：

- 将 GEWU 的代码、配置、资源直接复制进本仓库；
- 在本仓库文档中混淆两个产品的定位、功能描述或业务边界；
- 把 GEWU 的产品决策当作 AUTOVERSE 的决策依据。

## 4. 证据分级标准

所有研究结论必须标注证据等级，未来引用时必须保留该标注：

| 等级 | 含义 |
| --- | --- |
| **V（Verified）** | 已在本机/原型中真实运行并验证，附运行记录 |
| **R（Researched）** | 基于官方文档、官方仓库、可复现资料的研究结论 |
| **O（Opinion）** | 社区观点或经验推测，仅供参考，不作为决策依据 |
| **U（Unverified）** | 未能核实的信息，明确标注"未能核实" |

禁止将 U、O 级信息写成 R、V 级结论。禁止编造 Skill、开源项目、模型资源或技术能力。

## 5. 工作循环

每个研究/验证阶段遵循：

```text
立项（明确问题与验收标准）
→ 研究（官方资料优先，记录来源与核实日期）
→ 原型验证（可运行、可复现）
→ 记录（结论 + 证据等级 + 来源 + 局限）
→ 评审（自审 + 阶段报告）
→ 归档（Git Commit + Push）
```

## 6. 决策规则

1. **选型必须双证据**：文献研究（R）+ 原型验证（V），缺一不可进入正式方案。
2. **Design System 优先**：项目自身设计规范效力高于任何外部 UI Skill 或组件库审美。
3. **不得擅自变更架构**：核心技术架构变更需在本章程或架构报告中显式记录理由。
4. **不引入未评估的依赖**：新依赖必须记录版本、许可、维护活跃度、引入理由。
5. **合规红线**：不提交任何 API Key、Token、密码、.env；不使用许可不明或不可商用的资源；外部登录/授权/验证码/付费资源集中提醒项目所有者处理。

## 7. 交付纪律

- 每阶段更新 CHANGELOG.md 与 docs/09-handoff/；
- 报告必须区分：**已完成并验证 / 仅有研究结论 / 未开始**；
- 不为交付速度牺牲研究质量，允许"未完成但如实记录"。
