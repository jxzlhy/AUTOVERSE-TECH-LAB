0. 最高优先级指令

从现在开始，你正式接管 AUTOVERSE TECH LAB 项目。

本任务不是又一轮技术研究，也不是单纯的代码重构，更不是继续无限延长 Phase 2。

你的核心任务：一次性完成 Phase 2 最终收尾，然后立即进入 Phase 3，开始真正的 AUTOVERSE 正式产品开发。

本任务分为两个连续阶段：

* GATE A：Phase 2 Final Gate，最终工程验收与必要修复。
* GATE B：Phase 3 Product Development，正式产品建设。

必须连续执行，不要在两个阶段之间停下来等待用户批准。

不允许的行为

1. 不允许把 Phase 2 再拆成 Phase 2I、2J、2K 等无限延长的阶段。
2. 不允许反复进行没有实际产出的架构研究。
3. 不允许只写规划文档而不开发实际产品。
4. 不允许每完成一个小任务就等待用户确认。
5. 不允许因为部分非关键问题而阻止正式产品开发。
6. 不允许为了追求完美而不断重写已有可用架构。
7. 不允许把程序化示意模型包装成真实机械拆解模型。
8. 不允许虚构测试通过、性能数据、模型来源、授权信息或 CI 状态。
9. 不允许为了完成任务而擅自推翻仓库现有章程。
10. 不允许将技术实验室的研究成果与最终产品混为一谈。

最终目标：让项目从技术验证平台真正迈向一个具有高品质 3D 体验、丰富汽车内容、沉浸式探索和持续扩展能力的产品。

3. CI 和构建流程

全面检查根目录 package.json、各 workspace scripts 和 GitHub Actions。

重点检查：

* 是否使用 || true。
* 是否使用 || 将关键构建失败掩盖为成功。
* 是否存在失败后仍返回成功退出码的脚本。
* 是否存在没有真正执行的测试。
* 是否存在只检查部分 Packages 的构建流程。
* 是否存在测试与生产构建使用不同配置的问题。

要求：

1. 核心构建失败必须让 CI 失败。
2. 核心测试失败必须让 CI 失败。
3. 不允许用 fallback 掩盖真实失败。
4. 所有主要原型必须有明确的构建验证。
5. 核心 Packages 必须有明确的测试覆盖。
6. Playwright 必须能够在 CI 环境中真实启动和执行。
7. CI 输出应当能明确定位失败原因。

如果有合理的非阻断性任务，可以独立标记，不得影响核心构建状态的真实性。

4. 3D Runtime 工程质量验收

* 两阶段切换。
* 切换失败后的恢复。
* 重复进入和退出。
* 异常情况下的状态一致性。
* 旧场景资源释放。
* 新场景加载失败时的回滚能力。

AssetManager

* GLB 加载。
* Draco。
* KTX2。
* Meshopt。
* 加载失败处理。
* 重复请求处理。
* 缓存管理。
* 资源引用关系。
* 资源释放时机。

ResourceLedger

* 共享资源引用计数。
* 重复引用。
* 多场景共享。
* 引用归零后的释放。
* 防止提前释放仍在使用的资源。
* 防止重复 dispose。
* 防止资源泄漏。

ResourceDisposer

* Geometry。
* Material。
* Texture。
* Shader 相关资源。
* Object3D 子树。
* 共享资源。
* 循环引用及边界情况。
* Dispose 后再次使用的异常情况。

其他

* 高频 3D 渲染数据不能无必要地进入 Vue/Pinia 响应式系统。
* Three.js Runtime 与业务 UI 保持合理解耦。
* GSAP 用于场景、镜头和 UI 动效。
* Three Animation System 用于 GLB 动画。
* 机械运动学独立管理。
* 生命周期必须有真实测试支持。

* 可以继续非阻断性的 Phase 3 开发。

13.5 真实资产优先

产品的长期竞争力离不开高质量真实资产。

模型优先级：

S 级：完整真实拆解模型。

* 外壳独立。
* 发动机独立。
* 底盘独立。
* 车轮独立。

* 外观完整。
* 结构合理。
* Mesh 层级良好。

C 级：普通占位模型。

优先格式：

* glTF。

2. 官方授权资源。
3. 明确允许使用的开源模型。
4. 许可清晰的第三方模型。

* 车型。
